# 玻璃字幕主观平滑方案

## 状态

2026-08-14 已实施自动化部分；需要真实 macOS 课堂音频验收。

## 问题边界

玻璃模式是单一、按 `segment_id` 升序排列的滚动投影。实时 ASR 与流式
翻译会反复更新最新记录；文本跨行、临时改短、或 late revision 改变上方记录
高度时，旧实现会立即重排所有可见 `LogItem` 并多次滚到最底部。文字本身即使
保留 stable prefix，整个视口仍会跟随每次高度变化而移动。

本方案只改变 Qt 展示层的高度和滚动策略：不改变 ASR、翻译请求、
`SubtitleEvent`、`SegmentStore`、文稿或刘海投影。

## 已失败方案：固定当前句舞台 + 历史隔离

该方案曾把当前句放入独立固定区域，历史列表作为另一块区域。目标是让历史在
当前句更新时不重排，但实机体验失败，已回退，不得恢复：

- 当前/历史交接时出现大片空白、排序感混乱，长句常在读完前被转移；
- 两个独立区域仍会在行数变化时整体移动，且跳动更显眼；
- 引入了透明度、关闭控件、窗口缩放和模式桥接的额外回归面；
- 它改变了用户熟悉的单一时间顺序阅读模型。

只有先完成真实 macOS 对照实验、并证明所有上述回归均消失，才允许重新评估。

## 当前实现契约

### 1. partial 高度单调

`LogItem` 的 provisional 内容只允许占用更多高度；短暂改写为更短文本时，保留
原行高形成局部空白，不拉动后续历史。进入 `final` 后立即按真实换行高度收紧一次。
在测量前必须解除 `QLabel.setFixedHeight()` 留下的 min/max 限制，否则 final 无法
可靠收紧。

### 2. 当前句增长缓冲

统一 `QVBoxLayout` 的最后保留一个透明 trailing widget。仅最新 partial 记录存在时
高度为 52 px；新句首次显示时，滚到底部会把这段空白显示在当前句下方。随着文本
变长，当前句优先消耗该可见空间，历史行保持位置。final 时缓冲归零。

这不是当前句舞台：它不复制记录、不改变排序、不单独管理历史，也不限制当前句
可见内容。

### 3. 锚点滚动与限频

- 新 segment 与 final 立即布局；普通 partial 几何重排最多每 100 ms 一次；
- 用户手动翻历史时，保持现有 `_follow_scroll_tail=False`，绝不自动移动；
- tail-following 时，不再在 `rangeChanged` 和每次 reflow 强制 `maximum()`；
- 最新 partial 的底部越过 viewport 下方 12 px 安全线后，滚动一次
  `overflow + 28 px`，预留下一次增长空间。

因此视口只在增长缓冲耗尽后才移动，且每次移动后仍有余量；没有使用逐帧动画，
避免把一次必要位移延长成肉眼可见的持续抖动。

## 验收

自动化：

1. partial 长文本改短后高度不缩；final 后可缩；
2. 最新 partial 有 trailing growth cushion，final 后为零；
3. 未越过安全线时 tail anchor 不改变 scrollbar value；越过后按 slack 批量前进；
4. 既有 long Chinese、手动滚动、双击刘海、缩放测试继续通过。

实机：连续系统音频 60–120 秒，观察中英换行、翻译临时改写、final 收敛、
新 segment 到来和手动翻历史。通过标准是历史不在每个 partial 时移动；允许在
缓冲耗尽、final 或新 segment 时发生少量明确位移。
